## 1. 现在的 Pi

代码在 `app/lib/schemes/pi/`。

| 文件 | 现在做什么 |
|------|------------|
| `index.js` | `PiExecutor`。`list` 不调模型；其它动作拼 inbox，调 `runPiTurn`，把 outbox 放进 `output` |
| `runTurn.js` | 优先动态加载 `piRunTurn.mjs`；失败或 `PI_LIGHTWEIGHT=1` / `PI_ENGINE=light` 时走轻量 JSON 补全 |
| `piRunTurn.mjs` | `createAgentSession` + `SessionManager`。工具写死 `read` / `grep` / `bash` / `write`。要求模型 `write` 出 `outbox.json` |
| `workspace.js` | 工作区 `{WORKSPACES_ROOT}/skill_{skillName}/sessions/{sessionId}/` |
| `model.js` | 把 `resolveLlm()` 的结果转成 Pi 模型 |
| `parseOutboxJson.js` | 解析 outbox |

依赖（`package.json`）：

| 包 | 现在 |
|----|------|
| `@earendil-works/pi-coding-agent` | `^0.77.0` |
| `@earendil-works/pi-agent-core` | `^0.77.0` |
| `@earendil-works/pi-ai` | `^0.77.0` |
| `jsonrepair` | `^3.12.0` |
| Node | `>=18`（Docker 已用 `node:22-alpine`） |

已加载、且 `scheme: 'pi'` 的技能只有 `note-skill`。它的路由、回调和 `note_entries` 落库是本轮要守住的业务。

编排在 `app/service/skillInvoke.js`，所有 scheme 共用：

```text
resolveLlm
  → beforeExecute / enrichContext
  → 若 memoryConfig.enabled：MemoryEngine.getContext
  → Executor.executeTask
  → 若 outbox.memory_ops：MemoryEngine.applyOps
  → 睡梦入队（现有逻辑）
  → persistResult / formatResponse
```

这条流水线不改顺序。Pi 升级只换 `executeTask` 内部怎么开会话。

## 2. 和目标的差距

| 点 | 现在 | 目标 |
|----|------|------|
| Pi 版本 | `0.77` | 三个包一起到 `^1.1.0` |
| 人设与技能从哪读 | 启动时把 `SKILL.md`、`AGENTS.md` 拷进工作区，缺文件才写 | 从插件目录读。工作区不再留第二份文案 |
| 工具 | 四个内置工具写死 | 通用工具留在方案里；业务工具由插件登记，经 `defineTool` 装进会话 |
| 短期记忆 | 有 `session.jsonl`，压缩后的截断和失败兜底没有单独一层 | `schemes/pi` 里做截断和兜底。会话本体仍是 Pi |
| 长期记忆 | `memory_files/{skillName}/MEMORY.md`，另外工作区里还会写一份 `MEMORY.md` | 只保留 `memory_files/{projectId}/{skillName}/MEMORY.md`。工作区不再写第二份 |
| 项目 | skill 名全局唯一，路径里没有项目 | 每个 skill 声明 `project`。路径按项目分开 |
| 知识库 | 主应用没有只读知识库。`testgen-skill` 自己请求对端 BFF | 主应用增加按项目的只读根。现有对端调用不改道 |
| 确定性检查 | 没有 | Pi 技能可用 `modules/` 登记，运行时按名字调用。未登记则跳过 |

## 4. 调用链（升级后）

```text
HTTP（路径不变）
  → skillInvoke（顺序不变）
       → 用 skill.project 取记忆和知识库根
       → PiExecutor.executeTask
            → createAgentSession
            → DefaultResourceLoader 读 plugins/<skill>/ 的人设和 SKILL.md
            → 插件登记的业务工具
            → outbox
       → memory_ops 仍进 MemoryEngine
       → persistResult 仍由技能自己落库
```

`loop` / `react` / `langchain` / `action` 仍走各自 Executor。它们只在取记忆、知识库路径时多一个 `project`。
