# 03 — 业务开发模式

业务仍是 `plugins/<skill>/`。本轮优化的是 **Pi 技能怎么组织文件**。已经抛出的路由、回调和落库不改。

其它 scheme 的技能不套这套目录。它们只增加 `project` 字段，见 [04](./04-项目隔离-记忆与知识库.md)。

---

## 1. 两类技能，都在插件里

| 类型 | 谁用 | 形态 | 原因 |
|------|------|------|------|
| 场景说明 | 模型按场景读 | `SKILL.md`，多场景时放 `scenes/<name>/SKILL.md` | Pi 的 `DefaultResourceLoader` 会加载它。本仓不另写 prompt 运行时 |
| 给运行时调用的函数 | Pi 方案在固定时机调用 | `modules/<module>/<name>/index.js` 导出 `run(input)` | 要确定性执行，不交给模型分类 |

`note-skill` 保持单场景：根上的 `SKILL.md` 继续是唯一说明。不为它拆场景，也不强制加 `modules/`。

未登记的函数调用返回 `{ ok: false, reason: "skill_not_registered" }`。调用方跳过，不把这段文案写进对用户的 `reply`。

---

## 2. Pi 技能目录

```text
plugins/<skill-name>/
├── index.js                 # 现有导出。本轮只允许增加 project、config.pi
├── SKILL.md
├── prompts/                 # 没有则批次 4 从现有工作区文案迁一份
│   ├── AGENTS.md
│   ├── SOUL.md              # 可选
│   └── APPEND_SYSTEM.md     # 可选
├── scenes/                  # 只有多场景才建
│   └── <scene-name>/
│       └── SKILL.md
├── modules/                 # 可选
│   └── <module>/<name>/
│       ├── index.js         # run(input) => { ok, reason? }
│       └── README.md
└── tools/                   # 可选，业务工具定义
    └── index.js
```

`index.js` 里这些字段保持原样：`name`、`scheme`、`version`、`description`、`routes`、`dbTables`、`memoryConfig`、`callbacks`。

允许新增：

```javascript
project: 'platform',
config: {
  // 原有 llmDefaultProfile、actionDefaults 不动
  pi: {
    scenes: [],          // 空表示只用根上 SKILL.md
    tools: [],           // 额外业务工具名，空则沿用 Pi 内置四件
  },
},
```

回调签名不变：

| 回调 | 职责 |
|------|------|
| `beforeExecute` | 校验、补默认 `session_id` / `message` |
| `enrichContext` | 拼给执行器的输入。`note-skill` 的 `list` 和最近记事仍在这里 |
| `persistResult` | 落本技能的表。`note-skill` 仍写 `note_entries` |
| `formatResponse` | 仍返回 `reply` / `output` / `meta` |

主应用不在回调之外替技能做意图同义词匹配。

## 3. `note-skill` 必须保持的行为

| 项 | 现在 | 升级后 |
|----|------|--------|
| `POST /api/skills/note/chat` | 对话 | 同路径、同方法 |
| `POST /api/skills/note/chat/stream` | SSE | 事件名不变 |
| `action=list` | 读 `note_entries`，不调模型，不落库 | 仍在 `PiExecutor` 里短路，不进入 `createAgentSession` |
| `action=chat` | inbox 含当前消息和最近记事 | 同样的拼法 |
| 落库 | `persistResult` → `note_entries` | 不改表、不改字段 |
| 记忆 | `memoryConfig.type = file`，`memory_ops` 合并 | 文件改到项目目录，见 04。API 仍用 `note-skill` 这个名字 |
| 无密钥 | 返回「未配置 LLM」的开发模式 outbox | 文案和 `message_type: text` 保持 |

outbox 必填仍是 `reply`、`message_type`、`intent`、`agent_name`。缺 outbox 时执行器仍写入一条 `intent: error` 的兜底，不让请求挂死。

## 4. 运行时何时调用 `modules`

只在 Pi 方案里、只调用 **当前技能** 登记的函数。

| 时机 | 调用 |
|------|------|
| 解析出 outbox 之后、交给 `persistResult` 之前 | `modules/verification/<name>`，若该技能登记了 |
| 其它 | 本轮不增加 |

`note-skill` 不登记 verification 函数。因此这条调用对它是空操作，`persistResult` 仍会执行。

函数不得调用模型，不得读取别的项目的记忆或知识库。

---

## 5. 和健身仓模版的差别

健身仓用 `src/http` + `service.read/write` 编排回合。本仓库的业务出入口已经是 Skill 路由和 `callbacks`。不要在插件里再造一套 `http/`、`service/read`、`service/write`。

新增 Pi 技能时复制 [示例/新增pi-skill.md](./示例/新增pi-skill.md)。新增项目时复制 [示例/登记项目.md](./示例/登记项目.md)。
