# 04 — 项目隔离、记忆与知识库

一个进程里有小说、健身、运维、测试生成和平台示例。记忆文件、向量行、工作区、知识库按项目分开。对外仍用 skill 名访问，因为 skill 名全局唯一，调用方不用改 URL。

---

## 1. 项目登记

新增 `config/projects.json`（可提交，不含密钥）：

```json
{
  "projects": [
    {
      "id": "platform",
      "title": "平台示例",
      "skills": [
        "note-skill",
        "weather-skill",
        "research-skill",
        "qa-skill",
        "perf-bottleneck-skill"
      ]
    },
    {
      "id": "novel",
      "title": "小说",
      "skills": [
        "novel-brainstorm-skill",
        "novel-writer-skill",
        "novel-orchestrator-skill"
      ]
    },
    {
      "id": "fitness",
      "title": "健身",
      "skills": [
        "fitness-judge-skill",
        "fitness-observation-match-skill",
        "fitness-sample-skill",
        "fitness-config-skill",
        "fitness-explore-skill"
      ]
    },
    {
      "id": "ops",
      "title": "运维",
      "skills": [ "ops-project-skill", "ops-deploy-skill" ]
    },
    {
      "id": "testgen",
      "title": "测试生成",
      "skills": [ "testgen-skill", "api-template-skill" ]
    }
  ]
}
```

每个 `plugins/<skill>/index.js` 增加 `project`，值等于上表的 `id`。启动时 `PluginManager` 做交叉检查：

| 情况 | 行为 |
|------|------|
| 已加载 skill 没有 `project`，或 `project` 不在登记表 | 拒绝加载该 skill，打错误日志 |
| 登记表里的名字没有对应已加载 skill | 打警告，不阻断启动。`novel-review-skill` 就属于这种：目录在，没有 `index.js` |
| 同一个 skill 名出现在两个项目 | 拒绝启动 |
| 登记表与 `index.js` 的 `project` 不一致 | 拒绝加载该 skill |

登记表是「当前关联了多少项目、每个项目有哪些 skill」的唯一清单。不要在代码里再写一份项目枚举。

### 1.1 新增只读接口

`GET /api/projects`

```json
{
  "count": 5,
  "projects": [
    {
      "id": "platform",
      "title": "平台示例",
      "skills": [
        { "name": "note-skill", "scheme": "pi", "memory": "file" }
      ]
    }
  ]
}
```

`count` 是项目数。`skills` 只含本次实际加载成功的技能。这个接口不替代 `/api/plugins`。

`/api/plugins` 与 `/api/plugins/:name` 的已有字段保留，每条多一个 `project`。

## 2. 路径

`projectId`、`skillName` 写入路径前只保留 `[a-zA-Z0-9_-]`，与现在的 `sanitize` 相同。

| 数据 | 现在 | 目标 |
|------|------|------|
| 文件记忆 | `memory_files/{skillName}/MEMORY.md` | `memory_files/{projectId}/{skillName}/MEMORY.md` |
| 工作区 | `workspaces/skill_{skillName}/` | `workspaces/{projectId}/skill_{skillName}/` |
| 知识库 | 无 | `knowledge/{projectId}/`，根由 `KNOWLEDGE_ROOT` 指定，默认 `{baseDir}/knowledge` |
| 向量 | 每技能一张表 | 表名不变。读写带 `project_id` 列；旧行在首次访问时补上该技能的 `project` |

环境变量名不变：`MEMORY_FILES_DIR`、`WORKSPACES_ROOT`。新增 `KNOWLEDGE_ROOT`，不设置时用默认目录。

### 2.1 旧路径怎么读

批次 2 起，读文件记忆的顺序：

1. `memory_files/{projectId}/{skillName}/MEMORY.md`
2. 若第 1 个不存在，读 `memory_files/{skillName}/MEMORY.md`，并把内容复制到第 1 个路径后再读

写只写第 1 个路径。现有 `memory_files/note-skill/MEMORY.md` 因此不会丢。

工作区没有要迁移的业务真相（会话可以重新开始）。新会话写新路径。旧目录留着，批次 5 之后代码不再打开它。

工作区里的 `MEMORY.md` 停止创建。长期记忆只走 `memory_files`。`getContext` 注入的文本不变，所以模型仍能在本轮看到记忆摘要。

## 3. 记忆

`MemoryEngine` 的对外方法不变：`getContext`、`applyOps`、`read`、`append`、`search`、`listEnabled`。内部多传 `projectId`。

| 类型 | 谁在用 | 升级后 |
|------|--------|--------|
| file | `note-skill` | 路径加上项目。`memory_ops` 仍按 `append` 写入对应小节 |
| vector | `research-skill`（`research_memory`）、`testgen-skill`（`testgen_memory`） | 表不改名。查询条件加上 `project_id`，避免以后同表名串项目 |
| 睡梦 | `skillInvoke` 在记忆开启且有 `session_id` 时入队 | 保留。队列表增加 `project_id`，worker 只处理该项目该技能。不新增睡梦产品 |

文件记忆不替代技能自己的业务表。`note_entries`、`research_log`、`testgen_runs` 仍由各自 `persistResult` 写。

Pi 短期会话（jsonl）与这份长期记忆分开，见 [02](./02-Pi技术升级.md)。

`GET/POST /api/memory/:skillName` 的路径参数仍是 skill 名。服务端用登记表把名字换成项目，调用方不传 `project`。

## 4. 知识库

主应用目前没有知识库模块。本轮加只读层，默认没有任何技能打开它。

```text
app/lib/knowledge/
├── index.js     # search(projectId, query) 与 read(projectId, page)
├── search.js
└── read.js
```

规则：

- 根目录是 `{KNOWLEDGE_ROOT}/{projectId}/`。`read` 拒绝跳出该目录的路径。
- 不提供写接口。同步写入仍在各业务自己的仓库里做。
- 不把知识全文塞进每轮 inbox。Pi 技能若在 `config.pi.tools` 里列入 `search_knowledge`，模型通过工具按需查 **自己的项目**。
- `testgen-skill` 现有的对端知识接口调用保持原样，不改到这个目录。

未打开该工具的技能，请求和响应与现在一致。

---

## 5. 隔离规则

一次调用只能看到本技能所属项目的：

- `MEMORY.md` 或向量行
- 工作区
- 知识库目录

`note-skill` 读不到 `testgen` 的向量，`research-skill` 读不到 `note-skill` 的文件。检查放在 `MemoryEngine` 和 `knowledge/read`，不放在各个技能里各写一遍。
