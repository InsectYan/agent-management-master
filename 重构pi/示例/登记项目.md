# 登记项目

一个业务系统对应 `config/projects.json` 里的一个 `id`。同一系统的技能放在同一个 `id` 下，这样记忆和知识库不会串到别的系统。

---

## 1. 改登记表

在 `projects` 数组增加一项，或把新技能名追加到已有项目的 `skills`。

```json
{
  "id": "<project-id>",
  "title": "<给人看的名字>",
  "skills": [ "<skill-name>" ]
}
```

`id` 只用小写字母、数字、连字符。它会出现在目录名里：

- `memory_files/<project-id>/<skill-name>/`
- `workspaces/<project-id>/skill_<skill-name>/`
- `knowledge/<project-id>/`

## 2. 改技能

`plugins/<skill-name>/index.js` 增加：

```javascript
project: '<project-id>',
```

`project` 必须和登记表的 `id` 相同。一个技能只能属于一个项目。

## 3. 启动后核对

`GET /api/projects`：

- `count` 等于登记表里的项目数（没有加载成功的技能仍留在登记表里，但 `skills` 数组只列出加载成功的）。
- 新技能出现在对应 `id` 下，而不是出现在别的项目里。

`GET /api/memory/<skill-name>` 仍用技能名，不用项目 id。

## 4. 不要做的事

- 不要为了隔离再起一个主应用进程。
- 不要把别的项目的 `MEMORY.md` 拷进这个技能的目录。
- 不要让这个技能的工具读取 `knowledge/<别的项目>/`。
